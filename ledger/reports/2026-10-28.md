## Curator decisions under the owner's constraints (question 7)

The owner left question 7 to the curator, with two constraints: the most efficient structure for any AI to navigate and learn from, and as simple as possible, as structured as needed.

1. **Vocabularies:** the v3 lists (now 1.2 with `evidence_kinds`) are accepted as they stand; the review is closed. Values not yet used by any pack stay: they cost nothing, and adding new terms is what makes lists drift. New values still go to the owner.
2. **Status levels:** unchanged (candidate, reproduced, verified, deprecated). The curator sets `reproduced` when evidence arrives (another model, person or Revit version). `verified` stays the owner's sign-off, because a curator verifying its own filings would empty the word. No review queue for the owner: the curator asks only when a pack is reproduced and its checks pass.
3. **Index for agents (index_schema_version 1.1):** index.json shrinks from about 203 KB to 76 KB (−62%) and becomes a lookup file. Each pack keeps everything needed to choose it (title, use_when, not_for, api_terms, facets, status, failure pattern ids, the one-line lesson, path). The rule, validation and environment are read from the pack, as AGENTS.md already prescribed. Failure patterns keep id, name and evidence kind, and the full text lives in `failure_patterns_file`. The file has one line per entry, so it stays readable in diffs. `tools/arpl_search.py` returns the lesson and the rule file path.
