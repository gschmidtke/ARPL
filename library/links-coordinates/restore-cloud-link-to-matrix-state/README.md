**Intent:** a repair run brings every link of a host back to its link matrix row, the way linking created it: the right cloud model, exactly once, at the shared position, associated with the shared site, pinned, on its workset. Nothing is left for a person to clean up, and no dialog stops an unattended batch (owner rule, 2026-11-10).

Tested 2026-11-10 in Revit 2024.3 on the Snowdon Towers sample federation (ACC). Cases: link moved 11-28 m and rotated, link type removed, link unloaded, link on another workset, duplicate instance, Overlay/Attachment change, a wrong model GUID in the matrix, several deviations at once. Each case ran twice; the second run had to change nothing.

## Lesson
Shared-site binding is a stored relationship between a link instance and a site of the linked model, not a property of its position. Moving never creates it, and moving a bound link rewrites the linked model's coordinates. An un-shared link is the trace of a deliberate act: Revit makes a person un-share a link before it can be unpinned and moved. Re-creating the link to get the binding back would delete what is attached to it and erase that trace. The repair therefore restores position and pin, never re-creates an existing link, never moves a shared one, and names every link whose Shared Site a person must set after asking the discipline lead.

## Rule
1. Identity: loaded link -> GetLinkDocument().GetCloudModelPath() GUIDs; unloaded ACC link -> ExternalResourceReference.GetReferenceInformation() LinkedModelProjectId / LinkedModelModelId (observed 2024.3); file reference only for file-based links; name only when no identity can be read, and never over a link whose identity is known to be another model.
2. Load governed links before checking placement or binding (RevitLinkType.Load): an unloaded link always reads '<Not Shared>'. In a batch open all worksets; run with no other open document that has the same links loaded.
3. Check the host's active site first (FP74). Per instance (loaded): shared and in place -> nothing; shared and off position -> do NOT move (FP72), row error 'host and linked model coordinates disagree'; un-shared and in place -> pin, report 'Shared Site to set manually'; un-shared and off position -> move back (safe while un-shared), pin, report the same. Never delete and re-create an existing link to restore its Shared Site. Only a missing link is created, with ImportPlacement.Shared. After the placement pass, roll it back if any link type now has HasSaveablePositions() true.
4. The run status names the manual items ('OK — N link(s) need Shared Site set manually'); they are not row errors, and a second run reports them again without changing anything.
5. Register an IFailuresPreprocessor on every repair transaction (delete warnings, list them in the report); a run with anything unfixable says so in its status, never plain OK.
6. Run the repair twice: the second run must change nothing.
Alternative where policy allows (not this owner's): re-create un-shared links that have nothing attached; for file links, PublishCoordinates with the link location id binds an in-place instance without deletion (FP69).
7. Owner rule 2026-11-11: only what the matrix defines. Any link the matrix does not define for the host (another model, any local file link) is removed, with a report line naming it, the reason and what went with it (instances, annotations counted first). Cloud links whose identity cannot be read are listed, not removed. Links of disabled rows and nested links are kept. Nothing is removed when the host has no enabled rows. A link that only carries the matrix name never selects, blocks or is repointed for the row: the matrix link is created and the other one removed. LoadOnOpen = FALSE: unload at the end (handler on Application.FailuresProcessing around Unload).

## Validation
- Every link is at the Matrix position and pinned; every '<Not Shared>' link is named in the report as 'Shared Site to set manually'
- No existing link instance was deleted (ElementIds before and after the run are the same, apart from duplicates removed)
- No shared link was moved: HasSaveablePositions() is false on every link type after the run
- No modal dialog during the run; warnings listed in the report
- Second run: nothing created, moved or removed; the same manual items reported
- No link outside the matrix remains (except unidentifiable cloud links, which are listed); every removal is named in the report with what was removed with it
